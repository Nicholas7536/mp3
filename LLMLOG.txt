# MP3: APIed Piper - Backend Implementation Plan

## Goal Description
Implement the RESTful API for a task management / todo application ("Llama.io") using Node.js, Express, and Mongoose, backed by MongoDB Atlas. The endpoints manage `users` and `tasks` collections with support for JSON-encoded query filtering (`where`, `sort`, `select`, `skip`, `limit`, `count`), strict input validation, HTTP status codes, and bidirectional synchronization between user `pendingTasks` and task `assignedUser` / `assignedUserName`.

## Architecture & Data Models
### 1. User Model (models/user.js)
- name: String, required: true, trim: true
- email: String, required: true, unique: true, trim: true, lowercase: true
- pendingTasks: [String], default: []
- dateCreated: Date, default: Date.now

### 2. Task Model (models/task.js)
- name: String, required: true, trim: true
- description: String, default: ""
- deadline: Date, required: true
- completed: Boolean, default: false
- assignedUser: String, default: ""
- assignedUserName: String, default: "unassigned"
- dateCreated: Date, default: Date.now

## Proposed Changes
1. Modify models/user.js: Implement schema with name, email, pendingTasks, dateCreated.
2. Create models/task.js: Implement schema with name, description, deadline, completed, assignedUser, assignedUserName, dateCreated.
3. Create routes/helpers.js: JSON query parsing (where, sort, select, skip, limit, count) and validation ordering.
4. Create routes/users.js: GET, POST, GET/:id, PUT/:id, DELETE/:id with two-way sync.
5. Create routes/tasks.js: GET, POST, GET/:id, PUT/:id, DELETE/:id with two-way sync.
6. Modify routes/index.js: Register users and tasks routes.
7. Modify server.js: Connect mongoose with process.env.MONGODB_URI || process.env.MONGODBURI.
8. Local testing: Start server, test endpoints and error handling with curl commands.
